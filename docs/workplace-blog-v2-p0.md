# 직주근접 블로그 V2 P0

## 범위와 운영 원칙

PR #98 `docs/codex-workplace-apartment-blog-v2.md`를 기준으로 비교글 요청서·이미지 요청서·모바일 UI를 개선합니다.
사이트는 자료를 모으고 요청서·ZIP을 준비하며, 실제 판독·글·이미지 제작은 챗에서 수행합니다.
사이트 내부 AI 호출, 매매 데이터 자동 조회, 운영 DB 쓰기, 운영 배포는 포함하지 않습니다.
사용자 승인 전 main 병합/프로덕션 배포 금지.

## 사용 흐름

1. `/apartment-workplace`에서 근무지 유형·이름·지역·공식 주소·출입구·이동수단·희망 범위·거래 유형·예산을 입력합니다.
2. 실제 후보 3~5곳과 출처 메모를 기록합니다. 예산·주소·경로를 모르면 비워둡니다.
3. 조사 요청서 또는 최종 원고 요청서를 복사하고 ChatGPT에서 작업합니다.
4. 원고와 연결된 이미지 00~07 요청서를 각각 복사하거나 챗에서 엽니다.
   AI 설명 이미지 요청서와 사진 검색/직접 촬영 추천을 분리합니다. 이미지 미리보기·생성은 없습니다.
5. 기존 단지별 첨부·ZIP 전달·받은 원고 보관은 제작순서 03에 펼쳐 둡니다.
   첨부파일은 챗으로 자동 전송되지 않으므로 사용자가 직접 ZIP을 첨부합니다.

기존 localStorage 키와 입력값을 유지합니다. 새 공식 주소 필드는 비어 있는 상태로 추가됩니다.
체크박스는 점검 메모입니다. 체크 여부는 요청서의 검증 상태를 바꾸지 않습니다.

## 고정 구성

제목 3개 제안 → 짧은 도입 → **01 10초 비교표** → 02 근무지·출입구 → 03 후보 3~5곳 →
04 실제 이동 동선 → 05 실거래·주거비 → 06 실거주 → 07 발견 1개 → 08 Q&A 3개 →
09 결론·3줄 요약·조사일·출처.

후보를 입력하면 비교표 작업 틀에 입력한 이름만 보존합니다. 위치·면적·금액·경로·출처·상태는
검증 전 `needs_check`입니다. 후보를 입력하지 않으면 `후보 선정 필요`로 둡니다.
입력한 조사일을 거래일·원문 확인일로 오인하지 않도록 `(입력 조사일)`로 표시합니다.
표의 정확한 값은 챗에서 원자료와 대조해야 합니다. P0는 데이터 검증 엔진이 아닙니다.

이미지: 00 썸네일 1254×1254, 01~07 본문 1600×900.
01 근무지 / 02 생활권 / 03 후보 / 04 주거비 / 05 경로 / 06 생활 조건 / 07 발견·요약.
각 이미지에 한 메시지, 이미지 사이 설명 2~3줄을 요청합니다.
근거 없는 경로는 05 출입구·횡단보도·야간 확인 카드로 대체합니다.

## 스타필드 수원 미검증 사례

입력: 스타필드 수원 / 수원시 장안구 / 도보 / 희망 20분 이내 / 전체 거래 / 예산 미설정.
주소·실제 출입구·후보·금액·경로는 미입력 상태로 테스트합니다.
PR #98에 주소와 후보 예시가 있어도 현행 공식 원문·위치와 대조한 것으로 간주하지 않습니다.

예상 요청서 일부:

```text
공식 주소: 확인 필요(needs_check) / 실제 출입구: 확인 필요(needs_check)
선호 이동수단: 도보 / 희망 범위(검증 결과 아님): 20분 이내
거래 유형: 전체 / 예산: 미설정·임의 가정 금지
```

표 예시: 단지는 `후보 선정 필요`, 가격·전용면적·실제 경로·출처·상태는 모두 `needs_check`.
'20분 이내 추천 단지', 실제 가격, 이동 시간은 생성하지 않습니다.

## PR #97 / P1 분리 확인

확인한 PR #97 HEAD: `a2bce7c5debe754724331e9df03828fc027077c0`.
추가/변경 파일은 `AGENTS.md`, `docs/codex-molit-api.md`, `scripts/molit-trades.mjs`,
`tests/molit-trades.test.mjs`, `.github/workflows/verify-apartment-data.yml`입니다.
P0는 이 파일들을 변경하지 않습니다. PR #97을 병합하거나 CLI를 중복 구현하지 않습니다.

P1에서 재사용할 기존 서버 경로는 `lib/apartment-server.ts`의 매매 RTMS 정규화와
Supabase `apt_complexes`, `apt_trades`입니다. `apt_monthly_stats.area_group`은 개별 전용면적이 아닙니다.
정확한 식별·전용면적·계약일·층·금액·해제/수집일을 조회하는 읽기 전용 연결은 별도 PR로 진행해야 합니다.
매매 API만으로 전월세·현재 호가·실제 경로를 제공하지 않습니다.

## 검증과 한계

- `npm run build`: 새 요청서/전달 테스트와 기존 아파트·TOP3·분양·Paramma 등 189개 테스트 및 Next 빌드.
- 신규 테스트는 **요청서의 구성과 검증 규칙**을 검사합니다. 실제 거래·가격·이동시간 검증 결과를 의미하지 않습니다.
- 기존 아파트 매칭·데이터 품질 테스트가 단지 오인·소스 누락·면적 그룹의 기존 처리 회귀를 검사합니다.
- 브라우저에서 입력 저장·복원, 체크만으로 검증 완료 주장 없음, 복사, 챗 링크, 이미지 8슬롯, 모바일 가로 넘침을 점검합니다.
- P0에서는 국토부/전월세/호가/지도 실시간 조회나 사실 검증을 수행하지 않습니다.

## 제작 순서에 따른 화면 배치

01 근무지·조건 → 02 후보 조사·조사 요청서 → 03 후보별 자료 첨부·ZIP·챗 전달 →
04 자료 메모·비교글 요청서·챗 원고 붙여넣기 → 05 이미지 00~07 요청서 → 06 검수·원고 복사.
상단 단계 링크와 각 단계의 다음 링크로 이동합니다.
비교글 원고는 기존 비교글 localStorage 객체의 선택 필드 `articleText`에 추가 저장하며
이미지 요청서에 포함합니다. 기존 조건·후보·출처 메모·단지별 IndexedDB 첨부·원고는 유지됩니다.
중복 수동 입력·단지별 진행상태 선택·검색어 안내·초기화 메뉴는 제거했습니다. 기존 입력 데이터와 단지별 원고는 저장값과 ZIP에 보존되며, 기존 원고는 보관 영역에서 열 수 있습니다.
