범위: 이미지 00/01/02 요청서 표시 및 개별 복사 버튼

상태: 완료 확인

- 00 썸네일 요청서 생성 및 화면 표시
- 01 본문 이미지 01 요청서 생성 및 화면 표시
- 02 본문 이미지 02 요청서 생성 및 화면 표시
- 각 슬롯별 `요청서 복사 + ChatGPT`, `복사만` 버튼
- 개별 복사 로직: `copyImagePrompt(slotId, openChat)`
- 실제 프로덕션 렌더링에서 00/01/02 슬롯 및 버튼 문구 확인

## 현재 단계 2
범위: 이미지 00/01/02 업로드 → 미리보기 → 교체 + 복사만 클립보드 검증

### 실제 파일 확인
대상: `app/paramma-bulk/page.tsx`

코드상 확인:
- 00/01/02 각 슬롯에 파일 입력 존재
- 허용 형식: PNG/JPEG/WEBP
- 업로드는 `handleUpload(slotId, event)`에 연결
- 등록 후 `images[slotId]`를 통해 미리보기 `<img>` 표시
- 이미지가 있으면 버튼 문구가 `이미지 교체`로 변경
- 교체 시 새 이미지 변환/저장 성공 후 화면 상태를 교체
- 교체 처리에서 예외 발생 시 기존 `images[slotId]`를 제거하지 않으며 "기존 이미지 보존" 안내 로직 존재
- `복사만` 버튼은 `copyImagePrompt(slotId, false)`에 연결되고 내부에서 `navigator.clipboard.writeText(meta.prompt)` 호출

### 프로덕션 렌더링 확인
- /paramma-bulk 응답에서 00/01/02 슬롯 표시 확인
- `이미지 등록`, `이미지 미등록`, `요청서 복사 + ChatGPT`, `복사만` UI 문구 확인

### 실제 브라우저 상호작용 테스트
상태: 미확인

사유:
- 자동화 Chromium에서 production Vercel URL 접근 시 `ERR_BLOCKED_BY_ADMINISTRATOR` 발생
- 따라서 테스트 이미지 업로드, 미리보기 전환, 실제 교체, 의도적 교체 실패, 클립보드 read-back 검증은 실행하지 못함
- 코드만 보고 실제 성공했다고 표현하지 않음
