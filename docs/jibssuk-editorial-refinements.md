# 최종 보완 지침 적용

게시된 환경에 있던 누적 조사 변경을 그대로 이어받아 `feat/jibssuk-editorial-refinements`에서 보완했다. 이전 변경을 재적용하지 않았으며 게시·배포·원격 main 반영을 하지 않는다.

## 이번 변경

- `lib/jibssuk-editorial-policy.mjs`와 `.d.mts`: 집값쓱 전용 독자 관심·근거·제목 기준을 한곳에서 관리한다. 최초 조사, 추가 조사, 최종 원고와 이미지 요청서가 필요한 기준을 공유한다. 공통 Paramma 지침은 바꾸지 않는다.
- `lib/jibssuk-simple-workflow.mjs`: 선택 관점·발견·차이의 근거를 보존하며 나머지 보조 근거를 선별한다. 생략한 사실 ID와 원본 보존 위치를 명시한다. 주장이 길어도 중간을 자르지 않는다. 핵심 근거가 많으면 요청서도 길어질 수 있다. 무조건 숫자·뜻밖의 발견을 강요하는 문구를 완화한다.
- `lib/jibssuk-research-history.mjs`: 공급 회차·범위·값이 다른 사실을 중복으로 합치지 않는다. 기존 회차별 원본 저장과 ID 재연결은 유지한다.
- `app/jibssuk-queue/JibssukArticleWorkflow.tsx`: 추가 조사 요청서 바로 아래에 가져오기 버튼/직접 입력을 배치한다. 제목 수치·단위·사업 단계의 표현 차이를 참고 안내하며 원고를 자동 수정하지 않는다. 사건일·자료 기준일·AI의 확인 주장·자료 비교 메모를 표시한다. 저장 실패 시 이번 입력이 저장되지 않았음을 알린다. 자동 지도 근거와 선택 단지명도 저장한다.
- `lib/jibssuk-apartment-image-prompts.mjs`: 본문·제목과 이미지 수치 일치, 캐릭터의 선택적 사용 지침을 공유한다. 기존 1600×900 규격·슬롯·지도·사진 제약은 유지한다.
- `lib/research-studio.d.mts`: 선택적 근거 메타데이터 타입만 확장한다. 공통 런타임 파서 변경 없음.
- `tests/jibssuk-editorial-refinements.cjs`, `package.json`: A~F 소재·누적·분리·표현 안내 검사를 빌드에 포함한다.

## 검증 범위와 한계

압구정(기존 계획/지분계약), 과천(공급 회차), 화서(동일 면적 계약과 원인 추정 금지), 일반 뉴스(발견 없음), 3회 이상 누적 및 30개 초과 근거, 다른 채널 분리를 합성 자료로 검사한다. 실제 공시·분양공고·실거래를 외부에서 검증했다고 주장하지 않는다.

제목 검사는 보수적인 로컬 표현 안내다. 숫자의 다른 표기·환산이 맞아도 안내할 수 있으며, 질문의 의미나 인과관계를 완전히 판정하지 않는다. 의미·원문·제목 약속 검사는 최종 AI 요청서에서 별도로 요구한다. 오류가 없을 때 확인 화면이나 승인 절차를 추가하지 않는다.

최근 7일/필요 시 30일 뉴스 기반 글감 추천, 집값쓱 발행 큐, 네이버 서식·표 PNG, 이미지 슬롯·사진·지도 구현, 다른 제작실은 유지한다. 네이버 편집기에 실제 붙여넣기나 원격 지도·사진 조회, 외부 AI가 생성한 원고의 최종 품질은 별도 실사용 검증이 필요하다.

최종 결과: 신규 보완 테스트 7개 시나리오 직접 실행 통과. `npm run build`에서 테스트 파일 37개 통과, 실패 0개, 타입 검사·프로덕션 빌드 완료. Chromium에서 기존 v1 작업 복원, 추가 조사 3회, 제목 수치 안내, 본문 자동 변경 없음, 선택 관점·이미지 수동/자동 지도 근거·가격 메모·발행 상태 보존, 새로고침, 다른 채널 저장 보존을 확인했다. 페이지 런타임 오류 없음. 로컬 브라우저 검사만 수행했으며 배포/게시하지 않았다.
