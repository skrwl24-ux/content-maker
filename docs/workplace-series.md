# 직장 주변 아파트 시리즈 작업

`/apartment-workplace`의 단지별 시리즈 작업판에서 사용합니다.

1. 단지를 추가합니다. 근무지·출입구 → 단지정보 → 매매 실거래 → 전세 실거래 → 월세 실거래 → 현재 매물 → 도보 경로 → 글 작성 순서로 안내합니다. 각 단계에 자료 확인 사이트와 캡처 필수 항목이 표시됩니다.
2. 현재 단계에 해당하는 네이버부동산·지도 캡처 또는 스크롤 녹화를 첨부합니다. 첨부는 단지·자료 단계별로 분리됩니다. 기존 첨부는 분류 메뉴에서 단계에 배정할 수 있습니다.
   - PNG/JPEG/WebP, MP4/WebM/MOV. 파일당 50MB 이하, 영상 60초 이하.
   - 긴 이미지는 겹치는 구간으로 나누고 영상은 최대 12개 화면을 추출합니다.
   - 브라우저가 해당 영상 코덱을 지원해야 합니다. 각 화면을 크게 보고 글자가 읽히는지 확인하세요.
3. 분석할 화면을 선택합니다(한 번에 최대 12개, 요청 약 3.9MB 이하).
4. 분석 결과를 원자료와 대조하고 수정합니다. 반영할 필드를 선택합니다.
   기존 값이 있는 필드는 기본 선택하지 않으며, 선택 시 표시된 값으로 교체됩니다.
5. 다음 자료로 이동하고 마지막 ‘글 작성’ 단계에서 미확보 항목을 확인한 뒤 ‘중요한 내용만 글 작성’을 누릅니다. 서버 AI가 확인된 자료로 짧은 글을 작성합니다. AI 연결이 실패하면 기본 양식 초안을 생성하고 AI 작성 결과가 아님을 표시합니다. 자료가 없으면 사유를 남기고 진행할 수 있습니다.
   기존 원고를 재생성할 때 확인 창이 표시됩니다.

첨부 원본·분할 이미지·영상 추출 화면은 IndexedDB에 단지별로 보관됩니다.
입력값·원고·진행 상태는 기존 localStorage에 저장됩니다.
같은 브라우저에서만 복원되며 다른 기기로 동기화되지 않습니다.
현재 자료 단계와 미확보 사유도 저장됩니다. 첨부됨과 내용 반영됨은 사실 검증 완료를 의미하지 않습니다. 선택한 분석 화면과 검토 중인 결과는 임시 상태입니다. 반영 전에 다른 단지로 이동하면 다시 분석해야 합니다.
첨부 삭제는 보관된 파일과 추출 화면을 지우며, 이미 반영한 입력값이나 원고는 지우지 않습니다.

## 서버 설정

`OPENAI_API_KEY`를 서버 환경변수로 설정해야 자동 판독이 동작합니다.
모델은 `WORKPLACE_EVIDENCE_MODEL`, `OPENAI_TEXT_MODEL`, `gpt-4.1-mini` 순으로 선택합니다.
선택 모델은 Responses API 이미지 입력과 JSON Schema 출력을 지원해야 합니다. 최종 글 작성 모델은 `WORKPLACE_ARTICLE_MODEL`, `OPENAI_TEXT_MODEL`, `gpt-4.1-mini` 순서입니다. 최종 글 작성 요청에는 반영된 입력 자료만 보내며 이미지를 다시 보내지 않습니다.
AI 키는 클라이언트에 전달되지 않습니다. 분석 시 선택 이미지와 단지명·근무지·확인일을
OpenAI Responses API에 전송하며 `store: false`를 사용합니다.
키가 없으면 503 오류와 대체 수동 작업 안내를 표시하고 첨부는 유지합니다.

판독은 웹 실시간 조회나 사실 검증 완료를 의미하지 않습니다. 공급/전용면적, 시세/실거래/호가,
계약연도·갱신·해제 여부, 단지명, 출입구를 원자료와 대조하세요.
원문 링크가 없는 캡처는 캡처명·영상 시점이 출처이며 원문 대조 미완료로 기록합니다.

## 검증

- `node --test tests/workplace-evidence.cjs`: 입력 제한, 미설정 키, 이미지·출처 전달,
  결과 스키마, 서비스 실패 처리. AI 응답은 테스트 대역입니다.
- `npm run build`: 기존 테스트와 프로덕션 빌드.
- 브라우저 점검: 첨부 → 새로고침 → 복원, 이미지·영상 화면 추출, 단지 간 자료 분리,
  기존 값 보호, 결과 반영·원고 생성, 첨부 삭제.
